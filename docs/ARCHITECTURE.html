Key as-built decisions

  • rpicam-vid invoked once per 5-minute segment (not one long-running --segment process) — filename/timing control at capture start, ~1-2s inter-segment gap accepted.
  • Upload retry is startup-flush only — no continuous while-running retry loop. A failed segment stays queued until the next process start.
  • Device registration retries independently of device-ID persistence (a separate device_registered marker, not device.json existence) — closes a retry gap found by no-mistakes' review step.
  • Halt-path worker_thread.join() has no timeout — the CRITICAL LED is guaranteed to be the final state, never raced by a slow in-flight upload.

As-built gaps

Known, tracked deviations from the spec — not hidden, not yet fixed. Both previously tracked firmware gaps are closed; one hardware substitution is open:

Manual flag button wired (issue #18). main() registers a gpiozero listener on GPIO 17 (pull-up, 50ms bounce) whose handler debounces, writes the FLAG_YYYYMMDD_HHMMSS.marker, and hands it to a dedicated flag-upload worker thread that uploads it immediately (the gpiozero callback thread never touches the network); a 2s cooldown drops bounce/double-taps, and a failed upload leaves the marker queued for next-boot flush - the same retry contract as segments.
NetworkManager keyfile activated after write (issue #19). After onboarding, main() runs nmcli connection reload then nmcli connection up visio behind a ConnectionActivator protocol. On failure: CRITICAL LED, exit 1; keyfile + session are on disk, so systemd restart + NM autoconnect retry from there. Restart boots also retry the reload/up best-effort whenever the keyfile exists (NM does not reliably load dropped-in keyfiles on its own); that retry never fails the boot.
PiJuice deferred to a USB power bank (2026-07-21). The spec's PiJuice Zero pHAT is currently blocked on availability; bring-up and integration testing run on a generic USB power bank into the Pi's power input instead — no HAT, no I2C battery telemetry. Firmware handles this via a new VISIO_BATTERY_SOURCE config (pijuice default, or none → a new UnmeteredPowerReader that reports a fixed 100% so the halt/low-battery thresholds never false-trigger while mains-equivalent powered), and the preflight check treats missing PiJuice hardware as a warning, not a startup-blocking failure. See the provisioning & preflight spec. BatteryReader is a Protocol, so a real replacement (PiSugar 2/3, a generic I2C-fuel-gauge UPS HAT, or a hand-built TP4056/IP5306 + MAX17048 combo) is a contained future swap, not a firmware rewrite.

Cloud AI Pipeline

  • Audio (Whisper)
  • Motion (FFmpeg)
  • Scene (Claude Haiku)
  • Composite score
  • Highlight select
  • FFmpeg assembly
  • Push delivery

Composite score

base_score = 0.4 * scene_novelty + 0.3 * audio_activity + 0.2 * motion_intensity
score = base_score * 1.5  (if manually flagged)
      | base_score         (otherwise)

Weights are per-user, stored in score_weights, tunable via the mobile app.

Trigger (as-built): the pipeline runs as the nightly-reel GitHub Actions workflow - nightly cron at 19:00 UTC (02:00 device-local ICT), plus workflow_dispatch with an optional day input for manual runs. Supabase Edge Functions were ruled out (pipeline is Python + FFmpeg; Edge Functions run Deno), and the spec's pending-segment-count threshold trigger is not implemented. Keys a run cannot process land in pipeline_dlq for nightly retry; after 5 attempts the key is escalated and the device owner is notified via push.

Mobile Companion App

Today's Reel

Full-screen expo-video player, vintage toggle, share. Regenerate button not wired (no backend consumer).

Raw Footage

Per-segment thumbnail timeline (expo-video-thumbnails), include/exclude feedback, flag markers.

Device

Live battery/storage/upload status via Supabase Realtime with a stale banner on channel error. Re-onboard button opens a QR display screen encoding WiFi credentials plus the signed-in user's current Supabase session tokens.

Archive

Calendar heat-map of past reels, UTC-midnight-normalized 30-day range.

As-built (Epic 5 screen wiring, issue #8): playback uses expo-video, not Expo AV - expo-av is deprecated in current Expo SDKs and was only installed because this spec predates that deprecation. A bottom tab navigator composes all four screens behind real Supabase Auth (session restore + AsyncStorage persistence).
Regenerate bottom sheet not wired. It has no backend consumer yet, so it stays out of scope for issue #8; the regenerate button surfaces as inert/"not available yet" rather than functional.
WiFi re-onboarding QR screen - resolved. The Device tab's Re-onboard button now navigates to a @react-navigation/native-stack route rendering a form (SSID/password) then a react-native-qrcode-svg QR code, encoding the exact {ssid, password, user_access_token, user_refresh_token} shape firmware's parse_onboarding_qr_payload expects.
